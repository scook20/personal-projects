quill — On-Device Meeting Intelligence

Personal build — Engineer

A native macOS meeting recorder built to replace a cloud notetaker. It captures the microphone and system audio as two independent Core Audio process taps, which yields clean two-party speaker separation for free — no diarization model, no speaker-ID step. Transcription runs entirely on-device with Parakeet TDT 0.6B at roughly 20 seconds per hour of audio, and the finished note lands in my vault as plain files.

Every load-bearing choice here was measured rather than assumed. Note generation was built first on Apple's on-device model and tested against a real 12,000-word transcript: it inverted speaker attribution and dropped the specifics, so generation routes to Claude and the local model stays as the offline fallback. That single outbound call is pinned to one endpoint on an ephemeral session with redirects refused at the delegate. The audio itself never leaves the machine.

SwiftSwiftUICore Audio process taps Parakeet TDT 0.6BFluidAudioEventKit Claude APIKeychain

Built on an MIT-licensed capture core (digimata/quill). The meeting app, calendar layer, note pipeline, voice-note pipeline, and vault integration are mine.

Engineering decisions

  • SwiftUI over Electron — ~90 MB resident, against 300–600 MB plus a multi-GB bundled model
  • Two-track capture replaces a diarization model outright
  • Plain files, no database — every note stays readable without the app
  • Isolation is structural, not a guard: separate storage roots make cross-contamination unrepresentable
  • Hardened runtime, stable signing identity, config refused unless user-owned
